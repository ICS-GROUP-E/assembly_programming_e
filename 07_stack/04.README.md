# `04.asm` — A Stack Frame for Two Local Variables

**Source:** [`04.asm`](04.asm) · **Built with:** NASM (`elf32`) + `ld -m elf_i386` · **Observed with:** GDB

## What the program does

This program is functionally identical to `02.asm` (the only differences are
comments). `_start` calls `work`, which creates a stack frame, writes two local
variables into it, reads them back into registers, and returns.

> These are `BITS 32` programs, so the stack pointer is **ESP**. On an x86-64 CPU
> ESP is the low 32 bits of RSP, but in 32-bit mode only ESP is used and each
> push/pop moves it by 4 bytes.

```asm
_start:
    call work
    mov eax, 1          ; sys_exit
    xor ebx, ebx
    int 0x80

work:
    push ebp            ; save caller's frame pointer
    mov ebp, esp        ; new frame pointer
    sub esp, 8          ; space for two 4-byte locals
    mov dword [ebp - 4], 100
    mov dword [ebp - 8], 200
    mov eax, [ebp - 4]
    mov ebx, [ebp - 8]
    nop
    mov esp, ebp        ; release locals
    pop ebp             ; restore caller's frame pointer
    ret                 ; pop return address
```

## The stack at program entry

The kernel starts `_start` with `ESP = 0xffffc410`, pointing at `argc = 1`; the
remaining entries are the `argv` array (terminated by NULL) followed by `envp`.
`EBP` starts at 0. The stack grows toward lower addresses.

```
0xffffc410 : 0x00000001   <- ESP   (argc)
0xffffc414 : 0xffffc6bb            (argv[0])
0xffffc418 : 0x00000000            (NULL)
0xffffc41c : 0xffffc702            (envp[0])
```

## Step-by-step stack trace (observed)

| Step | Instruction | ESP | EBP | Explanation |
|------|-------------|----:|----:|-------------|
| 1 | `call work` | `0xffffc40c` | 0 | Pushes return address `0x08049005`, then jumps to `work`. |
| 2 | `push ebp` | `0xffffc408` | 0 | Saves caller `EBP` (0) at `0xffffc408`; `ESP -= 4`. |
| 3 | `mov ebp, esp` | `0xffffc408` | `0xffffc408` | `EBP` becomes the stable frame base. |
| 4 | `sub esp, 8` | `0xffffc400` | `0xffffc408` | Allocates two locals by moving `ESP` down 8 bytes. |
| 5 | `mov [ebp-4], 100` | `0xffffc400` | `0xffffc408` | Stores 100 at `0xffffc404`. |
| 6 | `mov [ebp-8], 200` | `0xffffc400` | `0xffffc408` | Stores 200 at `0xffffc400`. |
| 7 | `mov eax, [ebp-4]` | `0xffffc400` | `0xffffc408` | EAX = 100. |
| 8 | `mov ebx, [ebp-8]` | `0xffffc400` | `0xffffc408` | EBX = 200. |
| 9 | `mov esp, ebp` | `0xffffc408` | `0xffffc408` | Drops the 8 bytes of locals in one instruction. |
| 10 | `pop ebp` | `0xffffc40c` | 0 | Restores `EBP = 0`; `ESP` points at the return address. |
| 11 | `ret` | `0xffffc410` | 0 | Pops `0x08049005` into `EIP`; returns to `_start`. |

### Memory layout while the locals exist

After step 6 the observed frame was:

```
0xffffc400 : 0x000000c8   <- ESP   [ebp-8] = 200
0xffffc404 : 0x00000064             [ebp-4] = 100
0xffffc408 : 0x00000000   <- EBP   saved caller EBP
0xffffc40c : 0x08049005             return address
0xffffc410 : 0x00000001             argc
```

Two locals are addressed as `[EBP-4]` and `[EBP-8]`; the saved frame pointer is at
`[EBP]` and the return address at `[EBP+4]`. That is why local offsets are negative.

## Tearing the frame down

- `mov esp, ebp` sets `ESP` back to `0xffffc408`, so the 8 local bytes are no
  longer part of the stack (their contents remain in memory as stale data).
- `pop ebp` reads the saved caller `EBP` from `[ESP]` and moves `ESP` to
  `0xffffc40c`.
- `ret` reads the return address from `[ESP]` and moves `ESP` to `0xffffc410`,
  exactly the entry value.

## Observations from running it

- GDB at the `ret` instruction showed `EAX = 100`, `EBX = 200`, `EBP = 0`,
  `ESP = 0xffffc40c`, and `[ESP] = 0x08049005`. After returning, `ESP` was back
  to `0xffffc410`.
- The `sub esp, 8` reservation is what creates the local-variable area; the stack
  itself simply provides a contiguous, downward-growing block of writable memory.
- The program is silent and exits via `int 0x80`. In this sandbox the exit syscall
  is killed by seccomp (`SIGSYS`, shell status 159); `strace` shows the program
  requested `exit(0)`. GDB confirms the frame was fully unwound first.
