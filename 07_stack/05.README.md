# `05.asm` — LIFO Order with Two Pushes and Two Pops

**Source:** [`05.asm`](05.asm) · **Built with:** NASM (`elf32`) + `ld -m elf_i386` · **Observed with:** GDB

## What the program does

Two 32-bit values are put in `EAX` and `EBX`, pushed onto the stack, and then
popped back into `EBX` and `EAX`. The pops are made in the reverse order of the
pushes, which is exactly what LIFO requires if each value is to return to its
original register.

> These are `BITS 32` programs, so the stack pointer is **ESP**. On an x86-64 CPU
> ESP is the low 32 bits of RSP, but in 32-bit mode only ESP is used and each
> push/pop moves it by 4 bytes.

```asm
mov eax, 0x11223344
mov ebx, 0x1234

push eax            ; stack gets 0x11223344
push ebx            ; stack gets 0x00001234 on top
nop

pop ebx             ; EBX = 0x00001234 (the last value pushed)
pop eax             ; EAX = 0x11223344 (the first value pushed)
```

## The stack at program entry

`_start` begins with `ESP = 0xffffc410` pointing at `argc = 1`:

```
0xffffc410 : 0x00000001   <- ESP   (argc)
0xffffc414 : 0xffffc6bb            (argv[0])
0xffffc418 : 0x00000000            (NULL)
0xffffc41c : 0xffffc702            (envp[0])
```

`push` decrements `ESP` by 4 and stores the value; `pop` loads from `[ESP]` and
increments `ESP` by 4.

## Step-by-step stack trace (observed)

| # | Instruction | ESP before | ESP after | Stack top after | Register effect |
|---|-------------|-----------:|----------:|------------------|-----------------|
| 1 | `mov eax, 0x11223344` | `0xffffc410` | `0xffffc410` | `argc = 1` | EAX = `0x11223344` |
| 2 | `mov ebx, 0x1234` | `0xffffc410` | `0xffffc410` | `argc = 1` | EBX = `0x00001234` |
| 3 | `push eax` | `0xffffc410` | `0xffffc40c` | `0x11223344` | — |
| 4 | `push ebx` | `0xffffc40c` | `0xffffc408` | `0x00001234` | — |
| 5 | `nop` | `0xffffc408` | `0xffffc408` | `0x00001234` | — |
| 6 | `pop ebx` | `0xffffc408` | `0xffffc40c` | `0x11223344` | EBX = `0x00001234` |
| 7 | `pop eax` | `0xffffc40c` | `0xffffc410` | `argc = 1` | EAX = `0x11223344` |

### The stack at step 5 (both values pushed)

```
0xffffc408 : 0x00001234   <- ESP   (EBX value, pushed last)
0xffffc40c : 0x11223344             (EAX value, pushed first)
0xffffc410 : 0x00000001             (argc, pre-existing)
```

In memory the 32-bit values are stored little-endian, so the bytes at `0xffffc408`
are `34 12 00 00` and at `0xffffc40c` are `44 33 22 11`. GDB's `x/wx` display
reconstructs the hexadecimal dwords shown above.

The first `pop` must therefore be into `EBX`: the top of stack is the value that
was pushed from `EBX`. Popping into `EAX` first would have loaded `0x1234` into
`EAX` and swapped the two values.

## After the pops

`ESP` is back to `0xffffc410` and both registers hold their original values:

```
EAX = 0x11223344    EBX = 0x00001234    ESP = 0xffffc410
```

The popped memory is not cleared: `0x00001234` and `0x11223344` remain at
`0xffffc408`/`0xffffc40c` as stale bytes below the active stack pointer.

The program then overwrites `EAX` and `EBX` for the exit syscall
(`mov eax, 1` / `xor ebx, ebx`) and executes `int 0x80`, so the restored values
must be observed in GDB before the exit sequence.

## Observations from running it

- GDB confirmed the exact values after each operation: `EBX = 0x00001234` after
  the first pop and `EAX = 0x11223344` after the second.
- `ESP`: `0xffffc410 → 0xffffc40c → 0xffffc408` (pushes) and
  `0xffffc408 → 0xffffc40c → 0xffffc410` (pops).
- Because the pops are in reverse push order, the pair acts like a balanced
  save/restore. If the pop destinations were reversed, the same instructions
  would exchange the two values.
- The program prints nothing. In this sandbox the final `int 0x80` is killed by
  seccomp (`SIGSYS`, shell status 159); `strace` reports the requested
  `exit(0)`. The stack operations complete normally before that point.
