# `06.asm` — Push/Pop Round Trip, Second Version

**Source:** [`06.asm`](06.asm) · **Built with:** NASM (`elf32`) + `ld -m elf_i386` · **Observed with:** GDB

## What the program does

`06.asm` is functionally identical to `05.asm` — the machine code is the same; only
comments differ. It demonstrates that a stack is LIFO by pushing two values and
popping them back in reverse order.

> These are `BITS 32` programs, so the stack pointer is **ESP**. On an x86-64 CPU
> ESP is the low 32 bits of RSP, but in 32-bit mode only ESP is used and each
> push/pop moves it by 4 bytes.

```asm
mov eax, 0x11223344
mov ebx, 0x1234

push eax            ; push 0x11223344
push ebx            ; push 0x00001234 (now on top)
nop

pop ebx             ; recover 0x00001234 into EBX
pop eax             ; recover 0x11223344 into EAX

mov eax, 1          ; sys_exit
xor ebx, ebx
int 0x80
```

## The stack at program entry

Linux starts `_start` with `ESP = 0xffffc410`, pointing at `argc = 1`; above it
are the `argv` pointers (NULL-terminated) and environment pointers:

```
0xffffc410 : 0x00000001   <- ESP   (argc)
0xffffc414 : 0xffffc6bb            (argv[0])
0xffffc418 : 0x00000000            (NULL)
0xffffc41c : 0xffffc702            (envp[0])
```

`EBP` is 0 and is not used by this program.

## Step-by-step stack trace (observed)

| # | Instruction | ESP before | ESP after | Stack top after | Register effect |
|---|-------------|-----------:|----------:|------------------|-----------------|
| 1 | `mov eax, 0x11223344` | `0xffffc410` | `0xffffc410` | `argc = 1` | EAX = `0x11223344` |
| 2 | `mov ebx, 0x1234` | `0xffffc410` | `0xffffc410` | `argc = 1` | EBX = `0x00001234` |
| 3 | `push eax` | `0xffffc410` | `0xffffc40c` | `0x11223344` | — |
| 4 | `push ebx` | `0xffffc40c` | `0xffffc408` | `0x00001234` | — |
| 5 | `nop` | `0xffffc408` | `0xffffc408` | `0x00001234` | — |
| 6 | `pop ebx` | `0xffffc408` | `0xffffc40c` | `0x11223344` | EBX = `0x00001234` |
| 7 | `pop eax` | `0xffffc40c` | `0xffffc410` | `argc = 1` | EAX = `0x11223344` |

### Stack contents after both pushes

```
0xffffc408 : 0x00001234   <- ESP   (pushed second, popped first)
0xffffc40c : 0x11223344             (pushed first, popped second)
0xffffc410 : 0x00000001             (argc)
```

`push` stores the full 32-bit value (4 bytes) and lowers `ESP` by 4. The value
`0x1234` therefore occupies the four bytes `34 12 00 00` in little-endian order.
`pop` reads 4 bytes from `[ESP]` and raises `ESP` by 4; the bytes stay in memory
afterwards but are no longer part of the active stack.

## Why the pop order matters

The last item pushed is the first item available:

- `pop ebx` sees `0x00001234`, which is the value that came from `EBX`.
- `pop eax` then sees `0x11223344`, which came from `EAX`.

If the two `pop` instructions were exchanged (`pop eax` followed by `pop ebx`),
the values would be swapped between the registers. The present order restores
each register to its original value.

## End of the program

After both pops, `ESP = 0xffffc410`. The exit sequence overwrites `EAX` with 1 and
`EBX` with 0, then executes `int 0x80`:

```asm
mov eax, 1          ; sys_exit
xor ebx, ebx        ; status 0
int 0x80
```

The stack is balanced at exit; the saved values are only visible before the exit
setup runs.

## Observations from running it

- The rebuilt `06` binary's disassembly is identical to `05`; both runs produced
  the same stack addresses and values.
- GDB at the instruction after the first pop showed `EBX = 0x00001234`,
  `ESP = 0xffffc40c`; after the second pop, `EAX = 0x11223344`,
  `ESP = 0xffffc410`.
- There is no program output. In this sandboxed shell the final `int 0x80` is
  killed by seccomp (`SIGSYS`, reported as shell status 159), but `strace` shows
  `exit(0)` was requested. On a normal Linux host the process exits with 0.
- This second copy reinforces the key point: push/pop pairs must be balanced and
  are consumed in reverse order, otherwise the values end up in the wrong
  registers.
