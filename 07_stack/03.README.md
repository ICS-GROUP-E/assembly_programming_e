# `03.asm` — `call` / `ret` Without a Frame

**Source:** [`03.asm`](03.asm) · **Built with:** NASM (`elf32`) + `ld -m elf_i386` · **Observed with:** GDB

## What the program does

`_start` puts 10 in `EAX` and calls `calculate`. `calculate` adds 5 to `EAX` and
returns. There are **no local variables and no stack frame**: the only stack
activity is the return address pushed by `call` and popped by `ret`. Arguments and
the return value travel in registers.

> These are `BITS 32` programs, so the stack pointer is **ESP**. On an x86-64 CPU
> ESP is the low 32 bits of RSP, but in 32-bit mode only ESP is used and each
> push/pop moves it by 4 bytes.

```asm
_start:
    mov eax, 10
    call calculate

after_call:
    nop                 ; EAX is now 15
    mov eax, 1          ; sys_exit
    xor ebx, ebx
    int 0x80

calculate:
    add eax, 5
    ret
```

## Step-by-step stack trace (observed)

At `_start`, `ESP = 0xffffc410` points at `argc = 1`:

```
0xffffc410 : 0x00000001   <- ESP   (argc)
0xffffc414 : 0xffffc6bb            (argv[0])
0xffffc418 : 0x00000000            (NULL)
0xffffc41c : 0xffffc702            (envp[0])
```

| # | Instruction | ESP before | ESP after | Top of stack | Effect |
|---|-------------|-----------:|----------:|--------------|--------|
| 1 | `mov eax, 10` | `0xffffc410` | `0xffffc410` | `argc = 1` | EAX = 10 |
| 2 | `call calculate` | `0xffffc410` | `0xffffc40c` | `0x0804900a` | Pushes return address `after_call`, jumps to `calculate`. |
| 3 | `add eax, 5` | `0xffffc40c` | `0xffffc40c` | `0x0804900a` | EAX = 15; stack untouched. |
| 4 | `ret` | `0xffffc40c` | `0xffffc410` | `argc = 1` | Pops `0x0804900a` into `EIP`. |

While `calculate` is running, the stack contains only one temporary item:

```
0xffffc40c : 0x0804900a   <- ESP   return address into _start
0xffffc410 : 0x00000001            argc
```

This is the essential contract of `call`/`ret`:

- `call target` = `push` the address of the next instruction, then jump.
- `ret` = `pop` that address into `EIP`.

Because `calculate` never changes `ESP`, the return address stays exactly at the
top of the stack for the whole function.

## End of the program

After `ret`, execution resumes at `after_call` with `EAX = 15` and `ESP` back at
its original value. The program then loads the exit syscall number into `EAX`
(destroying the 15) and calls `int 0x80`.

## Observations from running it

- GDB showed `EAX = 10` immediately before the call, `EAX = 15` inside
  `calculate` at `ret`, and `EAX = 15` again at `after_call`.
- `ESP` went `0xffffc410 → 0xffffc40c` on `call` and `0xffffc40c → 0xffffc410`
  on `ret`: a clean −4/+4 round trip.
- At `after_call` the return address is still visible at `0xffffc40c` as stale
  data, even though `ESP` no longer points at it.
- The program has no output. In this sandbox the final `int 0x80` is terminated
  by seccomp (`SIGSYS`, shell status 159); `strace` shows the requested
  `exit(0)`. The stack behavior up to that point is unaffected.
- This program shows that stack frames are optional: a leaf function that needs
  no locals and no saved registers does not have to touch `ESP` at all.
