# `02.asm` — A Function Call and a Stack Frame

**Source:** [`02.asm`](02.asm) · **Built with:** NASM (`elf32`) + `ld -m elf_i386` · **Observed with:** GDB

## What the program does

`_start` calls a subroutine `work`. `work` builds a conventional stack frame, stores
two local variables in it, loads them into registers, then tears the frame down and
returns. The program then exits.

> These are `BITS 32` programs, so the stack pointer is **ESP**. On an x86-64 CPU
> ESP is the low 32 bits of RSP, but in 32-bit mode only ESP is used and each
> push/pop moves it by 4 bytes.

```asm
_start:
    call work
    mov eax, 1          ; sys_exit
    xor ebx, ebx
    int 0x80

work:
    push ebp            ; save caller's frame pointer
    mov ebp, esp        ; establish our frame pointer
    sub esp, 8          ; reserve 8 bytes for two locals
    mov dword [ebp - 4], 100
    mov dword [ebp - 8], 200
    mov eax, [ebp - 4]
    mov ebx, [ebp - 8]
    nop
    mov esp, ebp        ; discard locals
    pop ebp             ; restore caller's frame pointer
    ret                 ; return to _start
```

## Entering `_start`

The kernel enters the program with `ESP = 0xffffc410` pointing at `argc = 1`,
followed by `argv[0]`, a NULL terminator and the environment pointers. `EBP` is 0.

```
0xffffc410 : 0x00000001   <- ESP   (argc)
0xffffc414 : 0xffffc6bb            (argv[0])
0xffffc418 : 0x00000000            (NULL)
0xffffc41c : 0xffffc702            (envp[0])
```

## Step-by-step stack trace (observed)

| Step | Instruction | ESP | EBP | What is on the stack / what happened |
|------|-------------|----:|----:|--------------------------------------|
| 1 | `call work` | `0xffffc40c` | 0 | `call` pushes the return address `0x08049005` and jumps to `work`. |
| 2 | `push ebp` | `0xffffc408` | 0 | Saves the caller's `EBP` (`0`) at `0xffffc408`. |
| 3 | `mov ebp, esp` | `0xffffc408` | `0xffffc408` | `EBP` now marks the base of the frame. |
| 4 | `sub esp, 8` | `0xffffc400` | `0xffffc408` | Reserves 8 bytes of local space below `EBP`. |
| 5 | `mov [ebp-4], 100` | `0xffffc400` | `0xffffc408` | Writes 100 (`0x64`) at `0xffffc404`. |
| 6 | `mov [ebp-8], 200` | `0xffffc400` | `0xffffc408` | Writes 200 (`0xc8`) at `0xffffc400`. |
| 7 | `mov eax, [ebp-4]` | `0xffffc400` | `0xffffc408` | EAX = 100. |
| 8 | `mov ebx, [ebp-8]` | `0xffffc400` | `0xffffc408` | EBX = 200. |
| 9 | `mov esp, ebp` | `0xffffc408` | `0xffffc408` | Locals discarded; only the frame base remains. |
| 10 | `pop ebp` | `0xffffc40c` | 0 | Restores caller's `EBP`; `ESP` points at the return address. |
| 11 | `ret` | `0xffffc410` | 0 | Pops `0x08049005` into `EIP`; back in `_start`. |

### The frame in memory

After step 6 (locals written), the observed memory around the frame was:

```
0xffffc400 : 0x000000c8   <- ESP   local [ebp-8] = 200
0xffffc404 : 0x00000064             local [ebp-4] = 100
0xffffc408 : 0x00000000   <- EBP   saved caller EBP
0xffffc40c : 0x08049005             return address pushed by call
0xffffc410 : 0x00000001             argc
```

The offsets are negative because locals live **below** `EBP`, while the saved `EBP`
and return address live **at and above** `EBP`.

## Unwinding the frame

`mov esp, ebp` is the key cleanup instruction: it throws away both locals in one
move by restoring `ESP` to the frame base. `pop ebp` then restores the caller's
frame pointer, and `ret` pops the return address. The local values are still
physically in memory at `0xffffc400`/`0xffffc404`, but they are now below `ESP`
and therefore outside the active stack. `ESP` is exactly back to `0xffffc410`.

## Observations from running it

- At `ret`, GDB showed `EAX = 100`, `EBX = 200`, `EBP = 0`, `ESP = 0xffffc40c`
  with the return address `0x08049005` on top. After `ret`, `ESP = 0xffffc410`.
- The program returns cleanly to `_start`; there is no output.
- The call/return sequence moved `ESP` down by 4 (return address), then down by
  4 (saved `EBP`) and 8 (locals) — a 16-byte frame — and then unwound all of it.
- In this sandboxed shell the final `int 0x80` is killed by seccomp (`SIGSYS`,
  shell status 159), but `strace` confirms the program requested `exit(0)`.
  GDB confirms the stack was balanced before the exit attempt.
