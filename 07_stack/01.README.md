# `01.asm` — Push, Push, Pop, Pop

**Source:** [`01.asm`](01.asm) · **Built with:** NASM (`elf32`) + `ld -m elf_i386` · **Observed with:** GDB

## What the program does

This is the simplest expression of the x86 stack discipline: two registers are pushed
onto the stack and then popped back off into two other registers. Because a stack is
LIFO (last in, first out), the second value pushed is the first value popped.

> These are `BITS 32` programs, so the stack pointer is **ESP**. On an x86-64 CPU
> ESP is the low 32 bits of RSP, but in 32-bit mode only ESP is used and each
> push/pop moves it by 4 bytes.

```asm
mov eax, 100        ; EAX = 100
mov ebx, 200        ; EBX = 200
push eax            ; push 100
push ebx            ; push 200
nop
pop ecx             ; ECX = 200  (last pushed)
pop edx             ; EDX = 100  (first pushed)
```

## The stack before the program starts

On Linux, `_start` is entered with `ESP` pointing at the initial process stack:

```
ESP -> 0xffffc410 : 0x00000001   argc = 1
       0xffffc414 : 0xffffc6bb   argv[0] pointer
       0xffffc418 : 0x00000000   argv terminator (NULL)
       0xffffc41c : 0xffffc702   envp[0] pointer
```

In the observed run `ESP = 0xffffc410` and `EBP = 0x00000000`. (Absolute addresses
change between runs; the *relative* changes are the important part.)

## Step-by-step stack trace (observed)

The stack grows **downward**: `push` subtracts 4 from `ESP` and then stores a 32-bit
value; `pop` loads a 32-bit value from `[ESP]` and then adds 4 to `ESP`.

| # | Instruction | ESP before | ESP after | Top of stack after | Register effect |
|---|-------------|-----------:|----------:|--------------------|-----------------|
| 1 | `mov eax, 100` | `0xffffc410` | `0xffffc410` | `argc = 1` | EAX = 100 |
| 2 | `mov ebx, 200` | `0xffffc410` | `0xffffc410` | `argc = 1` | EBX = 200 |
| 3 | `push eax` | `0xffffc410` | `0xffffc40c` | `0x00000064` (100) | — |
| 4 | `push ebx` | `0xffffc40c` | `0xffffc408` | `0x000000c8` (200) | — |
| 5 | `nop` | `0xffffc408` | `0xffffc408` | `0x000000c8` | — |
| 6 | `pop ecx` | `0xffffc408` | `0xffffc40c` | `0x00000064` (100) | ECX = `0x000000c8` (200) |
| 7 | `pop edx` | `0xffffc40c` | `0xffffc410` | `argc = 1` | EDX = `0x00000064` (100) |

When both pushes are complete, the stack looks like this in memory:

```
0xffffc408 : 0x000000c8   <- ESP   (200, pushed second)
0xffffc40c : 0x00000064             (100, pushed first)
0xffffc410 : 0x00000001             (argc, pre-existing)
```

`pop` does **not** erase memory. After `pop ecx`, the value `0x000000c8` is still
physically present at `0xffffc408`; it is simply below the current `ESP` and no
longer part of the active stack. The next `push` would overwrite it.

## End of the program

```asm
mov eax, 1          ; sys_exit
xor ebx, ebx        ; status = 0
int 0x80
```

`ESP` has already returned to its entry value (`0xffffc410`), so the program exits
with a balanced stack. The exit setup overwrites the values that were being
demonstrated (`EAX` becomes 1 and `EBX` becomes 0), which is why the useful
observations are the register values *before* this block:

```
EAX = 100   EBX = 200   ECX = 200   EDX = 100
```

## Observations from running it

- The program produces no output; it only manipulates registers and the stack.
- GDB confirmed `ECX = 200` and `EDX = 100`, proving the LIFO order.
- `ESP` moved `0xffffc410 → 0xffffc40c → 0xffffc408` on the pushes and returned
  `0xffffc408 → 0xffffc40c → 0xffffc410` on the pops.
- In this sandboxed shell the final `int 0x80` is killed by the environment's
  seccomp filter (`SIGSYS`, reported by the shell as exit status 159). `strace`
  shows that the program itself requested `exit(0)`. On a normal Linux host the
  exit status is 0. Run it under GDB to observe the stack state before the exit.
